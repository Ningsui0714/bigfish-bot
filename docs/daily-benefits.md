## 使用

```bash
npm start
```

在“模型账号”中登录厂商，开启该账号参与模型路由，按需勾选“每天自动签到”，保存。下方“每日领鱼粮”提供：

1. **启用每日自动签到**：总开关，默认开启；只调度逐账号已勾选的账号，新账号默认不自动领取。
2. **一键签到**：处理所有已登录、已启用账号，不要求勾选自动签到；总开关仅控制自动调度。
3. **停止后续渠道**：等待已开始的渠道收尾，不再开启后续渠道；不声称撤回厂商已接受的请求。
4. **逐渠道结果**：进度、领取金额和单位、是否复用当天记录、余额刷新结果。

自动调度在应用启动 30 秒后首次检查，此后每分钟检查。日期使用 `Asia/Shanghai`，不依赖宿主系统时区。跨日与重启补查当天，关机不运行，不补领历史日期。改变开关后在下一次检查生效；也可手动运行。

| 渠道 | 权益方式 |
| --- | --- |
| TRAE、CodeArts、Qoder / 中国版、Loomy、MiniMax | 查询活动后领取 |
| Raccoon 小浣熊 | 自动发放，不发送每日签到请求 |
| ZCode | 在厂商页面完成人工验证 |
| Cline、Gemini | 没有独立每日签到；Gemini 随账号套餐刷新 |

## 状态与一致性

- 同一批次的并发点击复用同一个任务；原生客户端仍保留各账号的签到单飞锁。
- 发领取请求前先保存 `claiming`。已提交但结果不确定的请求保留 `uncertain`，当天不自动重发。
- `claimed` / `already-claimed` 当天复用；界面将复用的领取记录标为“今日已领（本地记录）”，不当作本次新增额度。
- `inactive` / `status-error` 等按原生客户端的退避时间重查。停用账号、退出账号、关闭自动签到后，不再开始其后续任务。
- Qoder 返回 `coversToday:false` 时存为 `previous-period`，15 分钟后可重新检查；不会用上一活动周期奖励把今天标记为完成。
- 单个渠道失败后继续其他渠道；先持久化领取回执，再刷新余额。余额查询失败不会覆盖领取成功。
- 金额按渠道和原始单位分别保留，不能把不同厂商的 credits 相加当作可通用余额。
- 任务和回执写入既有 AES-GCM 加密状态文件；浏览器配置只接受总开关，不接受伪造的任务结果。
- 上次进程中断的运行中任务在界面显示已中断，不伪装为仍运行；真正的领取是否已提交由账号回执决定。

## 文件与接口

- `standalone/server/benefits-state.mjs`：权益分类、结果规范化。
- `standalone/server/benefits.mjs`：统一队列、延迟启动、周期检查、停止后续任务。
- `standalone/server/accounts.mjs`：原生回执保留金额、单位、日期覆盖；已停用账号不自动领取。
- `standalone/server/trae.mjs`：保留现有登录与签到实现，补齐停用判断与回执单位。
- `standalone/server/store.mjs`：移除渠道迁移、加密结果存储、配置更新隔离。
- `standalone/ui/benefits.jsx`：每日领鱼粮面板。
- `GET /api/state`：新增 `benefits` 状态。
- `POST /api/benefits/run`：HTTP 202，立即返回批次状态，后台顺序处理。
- `POST /api/benefits/stop`：停止后续渠道。
- 原有 `/api/accounts/:id/checkin`、`/api/trae/checkin` 保留，复用原生单飞与回执。

所有接口沿用本地会话、Host / Origin / JSON 校验。应用只启动统一调度器，不再同时启动两套独立签到定时器。
