# 群聊 Agent：第一版改造记录

## 调研依据（2026-10-26）

参考 [MaiBot 官方群聊配置](https://docs.mai-mai.org/manual/configuration/bot-config) 的身份、昵称、聊天节奏和上下文配置，以及 [A_Memorix 官方文档](https://docs.mai-mai.org/manual/configuration/amemorix-config) 的记忆隔离和共享风险说明。它们将人格、参与和记忆作为独立配置面，而非仅修改回复提示词。

本次没有足够证据将用户提到的“大鲸鱼”锁定为某一个开源项目，也没有登录 QQ/Bilibili 冒充体验过实际机器人。采用上述可核查的一手资料作为设计参考，不声称复制其完整机制。

## 原问题

原 `applyQqGroupChatbotTrigger` 把几乎所有普通群消息标记为 addressed，接着队列逐条执行 DSH。只有三句评价指导，缺少发言预算、兴趣、静音和独立记忆。

## 现在的真实链路

QQ 收到消息 → 去重/访问策略 → GroupMind 观察与本地决策 → 静默 / 本地记忆交互 / DSH 生成 → 沉默或静音检查 → 实际投递 → 将机器人回复加入近期窗口。

- `group-mind.mjs`：可注入时钟和随机源的决策器；叫名、对话延续、兴趣概率、低信息过滤、繁忙抑制、冷却、预算、静音；近期上下文和明确笔记。
- `qq-bridge.mjs`：把上述机制接入真实消息入口与出站投递，不是未调用的样例；来源人格与聊天数据分开注入。
- `state-store.mjs`：利用已有原子落盘链保存显式笔记，旧状态无须手工迁移。
- `qq-runtime.mjs`：尚未决定接话的普通消息不触发 typing 提示。

近期上下文最多覆盖 128 个群，LRU 淘汰；静音和短时状态也会随淘汰或重启清除。记忆只保存本人主动要求的内容，归属使用 QQ sender ID，不依赖可冒用的昵称。默认召回仅本人当前群的笔记，不跨群共享，也不注入同群其他人的笔记。

## 验证

运行 `npm run check`：构建、390 条相对导入、客户端模块求值/设置渲染及全部自动化测试。
新增测试包括规则节奏、明确叫名、忙时旁听、按群预算、成功回复后的上下文、模型沉默、推理期间静音、访问拒绝、笔记隔离/删除/过期/真实落盘重载，以及长内容 JSON 上限。

未做真实 QQ 联调，没有验证平台是否向当前账号下发未 @ 消息；没有改动现有凭据或部署到运行实例。源码运行/本地插件加载后重启 DSH 生效；仓库旧的 0.1.0 tgz 没有重新发布，别拿旧包验证新行为。

## 明确的边界与下一步

这是规则门控与模型生成组合，不是全语义 Planner。兴趣是可配置关键词，对话延续是短窗和句式启发式；尚无语义话题追踪、向量检索、自动中期摘要、表情包选择、Bilibili 适配或空闲主动开话题。

人格属于 prompt 约束，不是独立的无工具聊天执行器；DSH 工具权限仍由原权限层管理。接话模型慢时也仍可能出现回复滞后。下一轮优先用真实群聊回放测量误插话和漏接话，再决定是否加入轻量语义 Planner 与独立聊天/任务执行通道。

“忘记我”删除本地社交笔记和近期窗口，不删除 DSH 会话和独立群历史。旧会话仍可能包含先前发送过的笔记；若需要强删除，必须同时处理这些存储。
