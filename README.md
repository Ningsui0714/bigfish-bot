大肥鱼是独立运行的 QQ 群聊助手。它会先判断这句话要不要接，再用你配置的模型回应；不是把每条消息转发给编程 Agent。

在本机界面里管理模型账号、QQ 连接、人设、接话节奏和记忆。**主应用不需要 DSH，也不依赖 OpenClaw。**

## 先跑起来

需要 **Node.js ≥ 22.19** 和 npm。

```sh
git clone https://github.com/Ningsui0714/bigfish-bot.git
cd bigfish-bot
npm --prefix standalone ci
npm run build
npm start
```

打开 **http://127.0.0.1:3210**。

1. **模型账号**：登录一个厂商账号，或配置自己的 OpenAI 兼容 API；获取模型列表，选择聊天模型并保存。
2. **互动实验室**：先试聊、调人设，确认真实模型调用正常。这里不会发消息到 QQ。
3. **QQ 接入**：选择官方 Bot 或 NapCat，完成连接并设置群 / 联系人白名单。
4. **人格与节奏**：设置昵称、话题兴趣、接话概率、冷却与安静时长。

只运行独立版时，不需要在仓库根目录安装旧 DSH 依赖。现在是本地 Web 应用，尚未打包成桌面安装器。

## 和普通转发 Bot 有什么不同

| 能力 | 具体行为 |
| --- | --- |
| 自然接话 | 区分明确 @、句首叫名、短时对话延续、兴趣话题和普通旁听候选，不是每条群消息都调用模型。 |
| 知道安静 | 有低信息过滤、复读抑制、冷却和每分钟被动回复预算；模型也可以选择保持沉默。 |
| 稳定人设 | 默认是蓝色、呆萌、贪吃的大肥鱼；昵称、设定、兴趣都可编辑，认真问题仍正常回答。 |
| 显式记忆 | 你说“记住”才留下笔记，可以查看、删除；按群与成员隔离，实验室和 QQ 不混用。 |
| 统一模型 | 同一个模型跨厂商合并为一个选项；底层保留原始调用 ID，不需要聊天前反复换厂商。 |
| 本地管理 | 设置、凭据与记忆加密落盘；不会自动公开成公网模型反代。 |

### 群里可以这样说

```text
大肥鱼，电影结尾你怎么看？
大肥鱼，安静
大肥鱼，可以说话了
大肥鱼，记住：我喜欢乌龙茶
大肥鱼，你记得我什么
大肥鱼，忘记我
```

“安静”暂停被动接话，明确 @ 仍可提问。近期上下文是有时限的本地窗口，不是永久保存整个群的聊天记录；默认笔记每人每群最多 8 条，保留 30 天。

## QQ 接入，两条路径

### 官方 QQ Bot：扫码绑定

1. 在「QQ 接入」选 **官方 QQ Bot**，点击 **获取 QQ 绑定二维码**。
2. 使用手机 QQ 扫码，在腾讯页面确认绑定自己管理的机器人。
3. 凭据自动加密保存到本机，随后用 **WebSocket 主动连接**官方网关，不用手抄 AppID / AppSecret，也不需要公网回调隧道。
4. 发消息后，在“最近收到的会话标识”加入允许的群 / 用户 OpenID；保存后重新连接。

二维码会自动刷新，也可取消。手填凭据、Webhook 回调方式保留在高级设置。**扫码绑定、网关连接、真实消息回复是三个不同状态。** 官方 Bot 能看到什么消息，取决于开放平台实际授权和推送范围。

### NapCat / OneBot 11：个人 QQ

1. 独立安装 NapCat，在 NapCat 中登录 QQ。
2. 新建 **WebSocket 服务端（正向 WS）**，消息格式选 **数组**，配置 Access Token。
3. 在大肥鱼填写相同的 WS 地址和 Token、允许的 QQ 群号，保存并连接。

这里用的是 OneBot Token，不是 NapCat WebUI 登录 Token；本项目不内置 NapCat。其他兼容 OneBot 11 正向 WS 的实现也可接入。

两条路径的白名单分开保存：NapCat 使用 QQ 数字 ID，官方 Bot 使用 OpenID。私聊默认关闭；群白名单为空时不会回应群消息。完整步骤见 [QQ 接入说明](standalone/QQ.md)。

| Gemini Code Assist | Google |
| Qoder / Qoder 中国版 | 阿里云 |

账号管理使用单个厂商下拉框，只展示当前选中渠道的账号。模型则在上方统一选择：例如兼容的 `DeepSeek V4.1 Flash` 与带日期的同版本别名会合并，**不会把不同代际、Pro、Flash 或预览版一概混在一起**。

- 同一逻辑模型有多个已登录渠道时，可以在请求尚未被上游接受前尝试备用渠道。
- 已接受的请求遇到解析失败或流中断，不再向别的厂商重复发送，避免重复消耗额度。
- 支持手动配置 OpenAI 兼容 API；本地兼容模型服务属于独立的模型设置，不是第三条 QQ 接入方式。
- 支持每日签到的渠道可单独开启自动签到。**只有应用运行时才执行**；按上海日期检查，不补领历史日期，领取结果不确定时不盲目重发。

账号渠道包含客户端协议适配，不等于厂商公开、稳定的第三方 API。登录、模型目录、权益和费用由厂商决定；本项目**不承诺无限免费或零费用**。详见 [账号与模型](standalone/ACCOUNTS.md)、[TRAE 适配记录](standalone/TRAE.md)。

## 数据、备份与运行

- 默认管理端口只监听 `127.0.0.1:3210`，有同源与会话校验，不要直接暴露到公网。
- 数据在 `standalone/data/`：`state.enc` 为 AES-256-GCM 密文，`local.key` 是对应本机密钥。这个目录、构建产物、登录二维码和账号测试截图不提交 Git。
- 关闭应用后备份**整个数据目录**，恢复时同时恢复密钥与密文。只有密文没有密钥，不能恢复账号和记忆。
- “忘记我”删除当前记忆和近期上下文，不会擦除你另外保存的历史备份。
- 外部模型会收到本轮所需的上下文与相关笔记；按需选择你信任的模型服务。
- 当前只有文字聊天，没有开放 shell、工具执行、任意文件访问，也未实现图片 / 语音 / 文件解析。

可选运行参数：

```sh
# 自定义管理端口
PORT=3212 npm start

# 使用自己的数据目录
BIGFISH_DATA_DIR=/absolute/path/to/bigfish-data npm start
```

## 开发与测试

```sh
npm run local:check    # 独立版前端构建 + 自动化测试
npm --prefix standalone run dev   # 监视前端重建，另开终端 npm start
```

要验证保留的旧兼容代码，再安装根目录依赖：

```sh
npm ci
npm run legacy:check  # 旧 bundle 构建、导入 / 客户端验证、兼容测试
npm run check         # 独立版 + 兼容层完整检查
```

```text
standalone/ui/             本地 React 控制台
standalone/server/         社交核心、账号适配、统一模型与 QQ 连接
standalone/public/         BigFish 图形标识与吉祥物
standalone/test/           独立版测试
src/channels/qq/           共享的群聊决策和历史兼容代码
docs/                     设计约定与旧版归档
```

项目由 `dsh-qq-free-bot` 演进而来。旧 DSH 插件说明移到 [历史归档](docs/legacy-dsh.md)，不是当前安装入口；旧 RPC 标识与数据键保留用于兼容，不做机械全局替换。
